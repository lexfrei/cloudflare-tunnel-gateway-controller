| SH-78 | should (lc) | CTRL | GAP | internal/controller/route_status.go `buildAcceptedCondition` (any per-parent sync error -> Status=False, Reason=Pending); internal/controller/route_syncer.go `errBrokenDataPlane` and `gatewayPlaneError` (unresolved dedicated data plane; refused tunnel claim) | Documented deviation. The spec lists Pending among the reasons for Accepted=**Unknown** -- "used with the Accepted when a controller has not yet reconciled the route" (`shared_types.go` `RouteReasonPending`, reason table at `shared_types.go` `RouteConditionAccepted`) -- while this controller pairs Reason=Pending with Status=**False**. The pairing is deliberate only for the permanent causes: a refused tunnel claim (GW-107; `applyTunnelOwnership` clears the transient mark, so the refusal never retries) and a dedicated data plane whose resolve failed with a deterministic `config.ErrInvalidParameters` -- for those the route is served nowhere until the Gateway is fixed, and Status=False is the honest polarity since Unknown would read as "not looked at yet". The other cause is retryable and is the GAP: a non-deterministic resolve failure is marked transient (`route_partition.go`) and requeued through `SyncResult.TransientBrokenKeys` (`route_syncer.go`) -- "the controller has not yet reconciled the route" under Status=Unknown is exactly what the spec describes. A failed tunnel document write no longer reaches route status at all. Predates v3.5 (`git show v3.4.2:internal/controller/route_status.go`, line 616 sets the same reason); v3.5 widened it to the refusal case. The reason NAME stays inside the standard enum (SH-31); recorded in limitations.md. |
